# CoffeeTimer 作業の一覧（第1版）

仕様書 `docs/spec.md`（第1版）と設計 `docs/architecture.md` をもとにした作業の一覧。

- 状態：`[ ]` 未着手 / `[~]` 作業中 / `[x]` 完了
- 1つの作業は半日以内。作業ごとにコミットする
- どの作業も「`npm run check` が通る」ことを完了の条件に含む（下の表では省略）。画面の作業は `npm run build` も通す
- ID の頭文字：B 土台 / E ロジック（engine）/ A AI 呼び出し（ai）/ S 保存（store）/ U 画面（ui）/ D 取扱説明書（docs）

## 進める順番（まとまり）

| まとまり | 作業 | できるようになること |
|---|---|---|
| 1. 土台 | B-01〜B-03 | 空のアプリが GitHub Pages で開ける |
| 2. 最初に使える版 | E-01〜E-06、S-01〜S-02、U-01〜U-09、D-01 | 手でレシピを作り、タイマーで淹れられる |
| 3. AI 読み取り | E-07〜E-08、A-01〜A-03、S-03、U-10〜U-12、D-02 | YouTube の URL・文章からレシピを作れる |
| 4. 淹れた記録 | E-09、S-04、U-13〜U-14、D-03 | 淹れた記録をつけて見返せる |
| 5. 受け渡し・バックアップ | E-10〜E-11、S-05、U-15〜U-16、D-04 | レシピを人に渡す・受け取る、バックアップ |

### [x] E-02 比率・注ぐ量・読み上げ文・一覧の並び

### [x] E-04 豆の量による換算
- 担当：engine-dev
- 依存：E-02
- 仕様書：8.2

  - `normalizeBeans(value)`：小数第1位に丸め、下限を守る

  - 換算後の注ぐ量が、丸めた後の目標量どうしの差になるテストが通る
  - 開始の時刻・完成時刻が変わらない、元のレシピが書き換わらない、目標量が空の手順は空のまま、のテストが通る

## 未決事項

仕様書に書かれていないため、設計では仮に決めた（または決めていない）点。オーナーの判断が要る。

1. **手でレシピを作る入り口**：仕様 6.1 の追加の方法は「URL・文章・ファイル」の3つで、「手で一から入れる」が無い。最初に使える版（AI の前）では必要なので「手で入れる」を置く案。第1版の完成後も残すか
2. **準備中に手順をタップしたとき**：仕様 8.3「そこから始める」は、すぐ進み始めるのか、位置だけ合わせて START を待つのか（暫定：すぐ進み始める）
3. **手順へ飛んだとき・飛び越えたときの合図**：飛んだ先の手順の音・読み上げを出すか。別のアプリから戻って手順を2つ以上飛び越えたとき、今の手順の合図だけ出すか（暫定：どちらも今の手順の合図だけ出す）
4. **目標量は整数か**：湯量は整数と決まっているが、目標量は決まっていない（暫定：整数）
5. **豆の量の下限・上限**：− ボタンでどこまで下げられるか、AI の返答で受け入れる値の範囲（暫定：豆 0.5〜200g、湯量 1〜5000g、湯温 0〜100℃、時間 0〜3600 秒）
6. **ml の扱い**：AI が「ml」で読み取ったとき 1ml = 1g として g にしてよいか（暫定：そうする）
7. **「動画を開けない」の見分け方**：Gemini がどんなエラーを返すかは実際に試して決める（暫定：400 のうちキー以外のエラー）。AI の読み取りに時間の上限（例：3分で打ち切り）を設けるか
8. **「同じレシピ・記録」の判定（バックアップ）**：ID が同じものを同じとする案。人から受け取ったレシピは毎回新しいレシピとして足す（同じファイルを2回読むと2件になる）でよいか
9. **バックアップを読み込んだときの設定**：音・読み上げの設定も読み込んだほうで上書きするか（暫定：上書きする）
10. **ページを読み込み直したときのタイマー**：iPhone がタブを閉じ直すなどでページが読み込み直されたとき、抽出中のタイマーを続けるか（仕様 8.3 は画面を消す・別のアプリに切り替える場合だけ）。暫定：続けない（準備に戻る）
11. **スマホの戻るボタン・戻る操作**：確認・編集画面やタイマー画面で、ブラウザの「戻る」を押したときにアプリ内の前の画面に戻すか（暫定：対応しない。ルーターの部品を入れないため）
12. **保存したデータが壊れていたとき**：退避して空で始める案でよいか、利用者に知らせる表示を出すか
13. **アイコンの絵柄**：仮のものを作る。オーナーが用意した絵柄に差し替えるか
14. **音の高さ・長さ、Wake Lock が使えないときの文言**：仕様にないため仮に決める（architecture.md 4.4、glossary.md）
15. **「やめる」の確認**：仕様 7「入力があれば確認する」を、開いたときから変更があれば確認する、と読む（AI の読み取り直後は、何も直していなければ確認なしで戻る）でよいか
